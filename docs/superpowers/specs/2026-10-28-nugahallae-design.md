# 누가할래 — 앱 전체 구성 설계

작성일: 2026-10-28 (1차 프로젝트 1일차) · 상태: 사용자 승인 (2026-10-28)

## 1. 의도와 이유

**누가할래**는 모임에서 "누가 할지"(벌칙·당번)를 정하는 순간을, 그냥 고르는 대신 **긴장감과 즐거움이 있는 작은 이벤트**로 바꾸는 앱인토스 미니앱이다.

- 계기: 예능 '틈만나면'에서 출연자들이 작은 게임으로 점심값 낼 사람을 정하는 장면이 재밌어 보였음.
- 원칙 ① **부담 없음**: 가입·로그인·이름 입력 없이 열자마자 쓴다.
- 원칙 ② **폰 하나**: 각자 앱을 깔거나 접속하지 않고, 폰 한 대를 돌려 가며 모두 함께한다.
- 성공 장면: 모두가 폰 한 대에 고개를 모으고 숨죽이다가, 벌칙자가 정해지는 순간 다 같이 환호한다.

출발점은 1일차 실습 `C:\Users\user\강의 실습\1일차 수업 자료\index.html`("밥 값 내기 콜?", 미니게임 10종 단일 HTML)이다. 이 파일은 **게임 로직 참고 자료**로만 쓰고 그대로 이식하지 않는다.

이 프로젝트는 AI NATIVE CAREER CAMP 2기 1차 프로젝트(5일) 과제이기도 하다. 과제 제출물: GitHub(README 포함), 발표 자료, 배포 주소 또는 시연 영상.

## 2. 목표 / 비목표 / 반목표

**목표 (이번 범위)**
- 홈 → 게임 준비(말 뽑기) → 게임 플레이 → 결과 공개 → 다시 홈 / 한 판 더, 이 **한 바퀴가 끝까지 도는 뼈대**.
- 게임을 나중에 하나씩 끼워 넣을 수 있는 **게임 부품 구조**.
- 뼈대 검증용 첫 게임 1종: **돌림판**.
- 앱인토스 게임 출시 체크리스트의 공통 항목 대응(아래 5절).

**비목표 (이번엔 안 함)**
- 나머지 게임(사다리, 악어, 폭탄 등)과 밈 게임(예: 잔 채우기) — 뼈대 승인 후 하나씩 따로 추가.
- 로그인, 서버, DB, 랭킹, 광고, 결제.
- 참가자 이름 입력, 생일 등 개인 정보 입력.
- 게임 카테고리 탭(기본/밈) 분리.

**반목표 (돌아가도 이러면 실패)**
- **싱거움**: 결과가 순식간에 나와 긴장감 없이 끝남.
- **버그**: 플레이 중 멈추거나, 빠른 연타·뒤로가기 등으로 흐름이 깨짐.
- **복잡함**: 처음 쓰는 사람이 게임을 시작하는 방법을 바로 못 찾음.
- **사행성으로 읽힘**: 돈·내기·당첨·베팅·카지노를 연상시키는 단어나 그림.

## 3. 제약

- **앱인토스 서비스 오픈 정책**: 사행성·복권·베팅성 콘텐츠 출시 불가. 앱 안의 어떤 문구·이미지에도 다음을 쓰지 않는다: 내기, 밥값, 돈, 쏘기, 당첨, 복불복, 💸, 카지노 칩 모양. 결과는 "걸렸다", "차례", "벌칙" 같은 놀이 표현을 쓴다.
- **저작권**: 예능 프로그램 이름, 연예인 얼굴·목소리, 캐릭터를 쓰지 않는다. 밈은 놀이 방식만 빌린다.
- **앱인토스 게임 출시 체크리스트** 대응 필수(5절).
- **WebView에서 TDS 사용 시 React 필요**: `@toss/tds-mobile`, `@toss/tds-mobile-ait`, `@emotion/react@^11`, `react@^18`.
- 외부 코드 실행(`eval`) 금지, 토스 도메인 밖으로 이동·임베드 금지, SSR 금지(CSR/SSG만).
- 5일 일정. 토스 검수는 일정 안에 끝나지 않을 수 있어 과제 제출용으로 **GitHub Pages 배포**를 별도로 둔다.

## 4. 결정된 사항

### 4-1. 만드는 방식 (Claude의 판단, 사용자 이의 없음)
- React + Vite WebView 미니앱. 하네스 `/ait:new`(create-ait-app)로 뼈대를 만들고 TDS와 `@apps-in-toss/web-framework` SDK를 붙인다.
- 같은 빌드를 GitHub Pages에도 배포한다. SDK 기능(햅틱, Storage, 뒤로가기 이벤트)은 토스 앱 밖에서 실패해도 앱이 정상 동작하도록 감싼다.
- **이번 범위의 완료 기준(Claude의 판단, 사용자 확인 대기)**: 토스용으로 빌드할 수 있는 상태 + GitHub Pages 배포 + 과제 제출. 앱인토스 콘솔 등록·샌드박스 실기기 테스트·검수 요청은 이번 범위 밖이다. `/ait:new`의 appName은 임시로 `nugahallae`를 쓰고, 콘솔 등록 시 맞춘다.

### 4-2. 화면 흐름 (사용자 결정)

```
홈 ──▶ 게임 준비(말 뽑기) ──▶ 게임 플레이 ──▶ 결과 공개
 ▲                                               │
 └────────────── 다른 게임 / 한 판 더 ◀───────────┘
```

**① 홈**
- 인원수 선택: 2~10명. 이름 입력 없음. (사용자 결정)
- 벌칙 한 줄 입력(선택). 예: "커피 사기". 비워 두면 결과에 벌칙 줄을 표시하지 않는다.
- 게임 카드 목록: **탭 없이 한 목록**. (사용자 결정) 각 카드는 아이콘, 이름, 한 줄 설명.
- TDS 사용: Top, ListRow, Button 등.

**② 게임 준비 — 말 뽑기** (사용자 결정)
- 게임 규칙 한 문단.
- 말 뽑기 진행:
  1. 인원수만큼의 말(색 + 동물)이 섞인 상태로 준비된다. 동물 풀에서 무작위로 인원수만큼 고른다.
  2. 폰을 돌려 가며 **한 사람씩 화면을 탭**한다.
  3. 탭할 때마다 **말 하나가 랜덤으로 공개**되고, 그 사람이 자기 말로 기억한다. 앱은 사람과 말의 연결을 모른다.
  4. **탭한 순서가 곧 게임 차례**다.
- 다음 사람에게 넘기기 전에 이전 말이 화면에서 가려져야 한다. 다음 사람이 앞사람 말을 보더라도 문제는 아니지만, 화면이 "다음 사람 탭하세요" 상태로 분명히 바뀌어야 한다.
- 모두 뽑으면 [시작] 버튼(TDS BottomCTA).

**③ 게임 플레이**
- 풀스크린. 상단에 현재 차례 말 표시(예: "🦊 빨간 여우 차례").
- 이 화면은 TDS 대신 **자체 디자인**(게임 분위기 우선).

**④ 결과 공개** (공통 화면, 모든 게임이 공유)
- 뜸 들이기 연출 → 걸린 말 공개("🦊 빨간 여우 걸렸다!") → 진동(SDK 햅틱 `success`) + 화면 효과.
- 벌칙이 입력돼 있으면 "벌칙: 커피 사기" 표시.
- 버튼: [한 판 더](같은 게임, 같은 인원, 말 뽑기부터 다시), [다른 게임](홈).

### 4-3. 말(참가자 표시) (사용자 결정 + 제안 수락)
- 말 = **색 + 동물 얼굴**. 최소 10종이 서로 색과 동물 모두 다르게 구분돼야 한다(색약 대비).
- 카지노 칩처럼 보이는 둥근 칩 모양은 쓰지 않는다. 보드게임 말 또는 동물 캐릭터 느낌.
- 이모지 기반이면 Tossface(`/ait:inject-tossface`)로 기기 간 모양을 맞춘다.

### 4-4. 게임 부품 구조 (Claude의 판단)
- 각 게임은 같은 모양의 모듈이다: **차례 순서대로 정렬된 말 목록을 받고, 끝나면 걸린 말 하나를 돌려준다.**
- 게임 메타 정보(아이디, 이름, 아이콘, 한 줄 설명, 규칙 문단)를 함께 가진다.
- 게임 목록은 한 곳에 등록된 배열이고, 새 게임은 파일 하나 추가 + 등록 한 줄로 끝나야 한다.
- 결과 연출은 공통 결과 화면이 담당하고 게임은 관여하지 않는다(환호 순간 품질을 한 곳에서 관리).

### 4-5. 첫 게임: 돌림판 — 탈락식 (사용자 결정)
- 인원수만큼 칸, 칸마다 말(색 + 동물).
- **차례대로 한 명씩 돌린다.** 화살표가 가리킨 말은 **"통과"**로 빠지고, 다음 회전부터 그 칸은 사라진다(남은 말만으로 판을 다시 나눈다).
- **마지막까지 남은 한 말이 걸린다.** (말이 2개 남았을 때 돌려 하나가 통과하면 나머지가 걸림)
- 돌리는 사람은 차례 순서대로지만, 걸리는 말은 회전 결과로 정해진다. 이미 통과한 말의 주인도 계속 돌려 줄 수 있다. 회전 담당자는 남은 인원 중 차례 순서로 넘기거나, 단순히 "누구든 돌려도 됨"으로 둬도 된다(빌더 판단, 단 화면에 누가 돌릴지 분명히 표시).
- **규칙을 화면에 분명히 표시한다.** 사람들은 보통 돌림판을 "한 번에 결정"으로 생각하므로, 게임 준비 화면 규칙과 플레이 화면 상단에 항상 "걸리면 통과! 마지막까지 남으면 벌칙"이 보여야 한다. 통과할 때마다 "🦊 빨간 여우 통과!"를 띄우고, 남은 말 수를 표시한다.
- 회전마다 **점점 느려지다 멈추는** 연출(사용자 결정: 빠른 게임은 연출로 시간을 끈다). 마지막 회전(2개 남음)은 더 길게 뜸을 들인다.
- 1일차 버전의 돌림판 로직(캔버스 그리기, 회전 각도로 칸 계산)을 참고한다.
- 게임 부품 구조(4-4)는 그대로: 차례 목록을 받아 걸린 말 하나를 돌려준다.

## 5. 앱인토스 공통 대응 (체크리스트)

- 닫기 버튼과 겹치지 않게 Safe Area(Dynamic Island 포함) 확보.
- 안드로이드 뒤로가기(`graniteEvent` `backEvent`): 홈이 아니면 이전 화면으로, 게임 중이면 "그만할까요?" 확인 후 홈.
- 앱 종료 시 확인 모달.
- 진입하자마자 바텀시트를 띄우지 않는다.
- 터치·화면 전환 반응 2초 이내, 10초 안에 첫 화면.
- 세로 모드 고정.
- 마지막 인원수·벌칙을 SDK `Storage`에 저장해 다시 열면 복원(토스 밖에서는 localStorage 대체, 실패해도 기본값으로 동작).
- 햅틱은 필요한 순간에만 호출(반복 호출 금지).
- 사운드는 이번 범위에서 넣지 않는다. 넣게 되면 On/Off와 백그라운드 시 정지가 필요하다.

## 6. 빌더에게 맡기는 것

- 폴더 구조, 상태 관리 방식, 라우팅 방식.
- 동물 10종과 색 조합의 구체적 선택(4-3 조건만 지키면 됨).
- 뜸 들이기 연출의 길이와 효과 세부(단, 너무 짧아 싱겁지 않게, 결과까지 체감 수 초).
- TDS 컴포넌트 세부 선택. TDS가 게임 분위기와 안 맞으면 홈·준비 화면의 색·아이콘만 조정하는 선에서 바꾼다(사용자: "일단 만들고 확인").
- GitHub Pages 배포 설정.

## 7. 나중에 정할 것 (이번 구현을 막지 않음)

- 과제 지표 확정. 후보: 처음 쓰는 사람이 첫 게임 시작까지 걸린 시간·탭 수, 한 판 소요 시간, 테스트 시나리오 중 오류 건수, "한 판 더" 비율.
- 인원이 많을 때 지루한지 → 사용자 테스트로 확인.
- 추가할 게임 목록과 순서, 밈 게임(잔 채우기 등) 설계.
- 앱인토스 등록 카테고리(게임/비게임)와 등급분류.
