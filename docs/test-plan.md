# 사용자 테스트 · 지표 측정 계획 — 누가할래

4일차 리뷰 그룹 상호 테스트와 5일차 발표의 "수치로 확인" 자료를 위한 계획입니다.
발표 직군: **개발** (중심 질문: "어떻게 동작하는가", 지표 예시: 정확도·응답 시간·오류율)

## 1. 목적

- 이 앱의 핵심 흐름(홈 → 게임 고르기 → 말 고르기 → 게임 → 결과)이 **처음 쓰는 사람 손에서 막힘없이 끝까지** 도는지 확인한다.
- 개선 전후를 **숫자로 비교**하고 이유를 설명할 수 있게 기록을 남긴다.
- 상호 테스트에서 나온 문제를 안정성(이상 입력·실패·빈 화면) 자료로 쓴다.

## 2. 지표

### 2-1. 이미 측정된 지표 (개선 전 → 후)

| # | 지표 | 개선 전 | 개선 후 | 측정 방법·근거 |
|---|---|---|---|---|
| A1 | **공정성(정확도)**: 선 따라 그리기에서 부정행위로 건너뛸 수 있는 길의 비율 | 최대 약 70% 건너뛰고도 완주 | 시뮬레이션 공격자가 **실제 최단 경로보다 짧게 가지 못함** (40개 시드, 공격자 이동거리 ÷ 중심선 길이 = 1.00, 최단 경로 = 0.85) | 리뷰 에이전트·구현 에이전트의 시뮬레이션. 재현 가능한 테스트(`trace/__tests__/logic.test.ts`) 포함 |
| A2 | **응답 시간**: 게임이 끝난 순간 → 결과 화면까지 | 효과 게임 1.9~2.2초, 기록형 게임 2.1초 | **0.5초**, 기록형 **1.2초** | 코드 상수(`src/games/shared/timing.ts`) + 게임별 테스트가 경계값(`END_EFFECT_MS - 1` / `END_EFFECT_MS`)을 검증 |
| A3 | **자동 테스트 수** | 1개(스모크) | 469개 (50개 파일) | `npm test` |

> **쓰지 않는 수치**: "번들 1.26MB → 220KB"는 토스 디자인 시스템 포함 빌드와 제외 빌드의 차이라서 개선 지표로 쓰지 않는다. 현재 데모 웹 빌드는 JS 286KB + CSS 34KB(게임 17개).

### 2-2. 4일차에 새로 측정할 지표

| # | 지표 | 정의 | 판정 기준(미리 정함) |
|---|---|---|---|
| B1 | **첫 게임 시작까지 걸린 시간** | 앱 홈이 보인 순간 → 게임 플레이 화면이 뜬 순간 (말 고르기 포함, 인원 4명 기준) | 평균 **60초 이하** |
| B2 | **첫 게임 시작까지 탭 수** | 위 구간의 탭 횟수 | 평균 **16탭 이하** (최소 필요: 게임 카드 1 + `말 뽑기 시작` 1 + 4명×(말 카드 1 + `확인했어요` 1) + `시작하기` 1 = 11탭, 인원수가 이미 4명일 때) |
| B3 | **과업 성공률** | 시나리오 S1~S4 중 도움 없이 끝낸 비율 | **80% 이상** |
| B4 | **발견된 오류 수** | 테스트 중 나온 버그·이상 동작 (심각도별) | 1차 N건 → 수정 후 2차 **0건(심각 이상)** |
| B5 | **막힌 지점** | 참가자가 멈칫하거나 질문한 곳 (건수, 위치) | 같은 지점에서 2명 이상 막히면 수정 대상 |

> B1·B2 "개선 전후" 비교: 1차(수정 전)와 2차(1차에서 나온 문제를 고친 뒤) 같은 시나리오로 다시 측정한다. 참가자가 같으면 학습 효과가 있으므로, 2차는 **1차에서 가장 어려워한 사람 1~2명**에게 다시 부탁하거나 **다른 사람(참가자 아닌 팀원)** 에게 맡기고 이를 기록에 적는다.

## 3. 참가자와 준비물

- 참가자: 리뷰 그룹 **개발 · PO · 디자인 · 마케팅 각 1명 (총 4명)**. 처음 앱을 쓰는 사람이 더 좋다.
- 진행자 1명(나) + 기록자 1명(참가자 중 돌아가며 또는 팀원).
- 기기: 참가자가 쓰는 **실제 휴대폰** 1대, 인터넷, 데모 링크 https://etchroot.github.io/nugahallae/ (처음 접속은 캐시 방지를 위해 주소 끝에 `?v=test1` 붙이기).
- 화면 녹화(가능하면)와 초시계. 시간은 기록자가 초 단위로 적는다.
- **손가락 룰렛은 4명이 모여서 한 폰에 손가락을 올려야 하므로** 이 시나리오(S4)는 4명이 같이 있을 때 한 번에 진행한다.

## 4. 시나리오 (진행자 안내 문구를 그대로 읽는다 — 힌트 금지)

| # | 상황 | 안내 문구 | 관찰할 것 |
|---|---|---|---|
| S1 | 게임 찾기 | "앱을 열고 **'사다리'** 게임을 찾아서 열어 보세요." | 검색을 쓰는지, 스크롤로 찾는지, 걸린 시간 |
| S2 | 한 판 완주 | "4명이서 **돌림판** 한 판을 끝까지 해 보세요. 벌칙자가 나오면 끝이에요." | B1·B2 측정, 말 고르기에서 막힌 곳, 규칙 이해 여부 |
| S3 | 다른 게임 | "결과를 보고 **다른 게임**으로 넘어가서 하나 더 해 보세요. 고르는 건 마음대로." | 결과 화면에서 다음 행동을 찾는지, 어떤 게임을 고르는지 |
| S4 | 손가락 룰렛 (4명 동시) | "**손가락 룰렛**을 골라서 4명이 같이 해 보세요." | 멀티터치가 실제 폰에서 도는지, 손가락 떼면 재시작이 이해되는지 |

### 이상 입력 시나리오 (안정성용 — 진행자가 직접 시도하거나 참가자에게 부탁)

| # | 시도 | 기대 동작 |
|---|---|---|
| E1 | 돌림판에서 **돌리기 버튼 연타** | 한 번만 돈다 |
| E2 | 말 고르기에서 **빠르게 두 번 탭** | 다음 사람 말이 보이지 않는다 |
| E3 | 게임 중 **홈 버튼으로 앱 전환 후 복귀** — 연타 대결 | 0회로 기록되지 않고 "다시 해 주세요", 같은 사람이 다시 |
| E4 | 게임 중 **앱 전환 후 복귀** — 잔 채우기(붓는 도중) | 물이 한꺼번에 쏟아지지 않고 그 자리에서 붓기가 멈춤 |
| E5 | 인원 **10명** 설정 후 사다리·돌림판 | 화면이 깨지지 않는다 |
| E6 | 검색창에 **없는 게임** 입력 | "'○○'에 맞는 게임이 없어요" |
| E7 | **다크 모드** 폰에서 열기 | 글씨가 읽힌다 |
| E8 | 앱을 닫았다 다시 열기 | 마지막 인원수 유지 |

> 안정성 평가(10점)는 "2가지 이상 방어를 시연"이므로 발표 시연에는 **E1·E2·E3**을 쓴다(자동 테스트로도 증명 가능).
>
> **웹 데모에서는 확인 안 되는 것**: 게임 중 안드로이드 뒤로가기 → "게임을 그만할까요?" 확인 창. 뒤로가기 처리는 토스 SDK를 통해서만 동작하므로, 웹 데모에서 브라우저 뒤로가기를 누르면 확인 창 없이 페이지를 벗어난다. 토스 샌드박스에서 따로 확인한다(자동 테스트로는 검증됨).

## 5. 진행 순서 (약 25분)

1. (2분) 목적 설명, "앱을 평가하는 것이지 사람을 평가하는 게 아니에요" 안내, 녹화 동의 확인
2. (3분) 사전 질문: 평소 모임에서 계산·당번 정할 때 뭘 쓰는지(가위바위보, 사다리 앱 등) — 문제 정의 근거로 사용
3. (10분) S1 → S2 → S3 (참가자 1명씩 번갈아)
4. (4분) S4 (4명 동시)
5. (4분) 이상 입력 E1~E8 중 되는 것
6. (2분) 마무리 질문: **다시 쓰고 싶은지(1~5점)**, 가장 재밌던 게임, 가장 불편했던 점

## 7. 일정 (4일차)

- 오전: 이 계획서 확정, 기록 양식 인쇄 또는 복사, 데모 링크·폰 점검
- 오후: 리뷰 그룹 **1차 테스트**
- 저녁: 오류 기록 정리 → 수정 → 데모 재배포
- 가능하면 저녁 또는 5일차 오전: **2차 테스트**(같은 시나리오), 집계표 채우기

## 8. 발표에서 쓰는 방법 (개발 직군)

- 3장 "설계 판단": 부정 방지 설계(A1), 응답 시간 설계(A2), 맞바꾼 것(예: 데모 웹 빌드에서 TDS를 바꿔 끼운 이유와 한계)
- 4장 "평가 리포트": A1~A3 + 집계표(B1~B5) 전후 비교, **실패 원인 분석**(예: 막힌 지점이 왜 생겼나)
- 한계: 참가자가 4명이라 통계적 결론이 아니라 **문제 발견용**이다. 직군별 1명씩이라 같은 직군 반복 테스트는 못 했다.

## 9. 알려진 한계·주의

- 손가락 룰렛 멀티터치는 이 테스트 전까지 **실제 폰에서 확인된 적이 없다**. 먼저 개발자 본인 폰으로 1회 리허설한다.
- 시간은 사람이 재므로 ±2초 오차가 있다. 녹화가 있으면 녹화에서 다시 잰다.
- 토스 앱 안(샌드박스)이 아니라 **웹 데모**로 테스트한다. 토스 앱에서의 뒤로가기·닫기 확인 창은 별도로 확인해야 한다(이번 테스트 범위 밖).
